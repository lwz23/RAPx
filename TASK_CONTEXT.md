## Decisions

- The user approved a fixture-closed minimum contract. New source, sink, predicate, P3-origin, and P6-boundary forms outside the 27 fixtures are unsupported/future work.
- P3 is limited to lifetime-extension transmute, `MaybeUninit<bool>::assume_init`, and unchecked UTF-8 validity.
- P6 is limited to an `extern "C"` out-pointer flowing to `NonNull::new_unchecked` and an open trait `usize` result flowing to `get_unchecked`.
- Keep the existing `-unsoundaudit` CLI and `LwzCheck::new(tcx).start()` entry point; replace its internal implementation and output schema directly.
- Keep project concurrency and Cargo jobs at one. Every build, test, control check, and scan uses a fresh target.
- Existing shell `RUSTFLAGS` are explicitly cleared. The build shell then sets only the handoff-mandated Z3 native search path.
- GitHub SSH uses `ssh.github.com:443` for transport while `origin` remains `git@github.com:lwz23/RAPx.git`.
- `rap-unit-v2.schema.json` is the Stage 1 interface contract. It closes top-level, pattern-count, finding, causal-key, span, source, obligation, validation, and propagation key sets.
- Finding IDs are canonical causal-key SHA-256 values; the canonical key excludes witness choice and propagation depth.
- Legacy `Cargo.toml` and `src/lib.rs` files remain byte-identical to the frozen handoff copies. New fixture pairs use the smallest safe construction APIs needed to make private-state roots reachable without changing their source classification.
- The one-shot fixture generation helper was not retained; the frozen crate sources, oracles, lockfiles, and manifest are the reviewable source of truth.
- The exact nightly's installed component set was not changed when `rustfmt` was absent. Stable rustfmt was used only as a mechanical formatter for the new standalone Rust source; compilation and tests remain pinned to nightly-2024-10-12.
- Local-call edges are accepted only after `Instance::try_resolve` returns a local MIR item; unresolved and ordinary external Rust calls remain opaque.
- Lifetime-transmute P3 is narrowed to an internal operand transmuted into the public function's `&'static` return shape; this remains a heuristic candidate form, not a proof of region unsoundness.
- Canonical fixture data remains only in `tests/unsoundaudit-v2/fixture_manifest.json`. No artifact copy was added because its relative legacy provenance path is meaningful from the canonical location.
- Raw final logs remain local and uncommitted; only their SHA-256 digests and the normalized deterministic result are tracked.
- Real-project results use pre-registered samples, labels, and stop lines. Standard-library findings become development data after any result-informed change and cannot then serve as an unseen precision holdout.
- `core`, `alloc`, and `std` are evaluated separately because crate-local analysis intentionally does not propagate across their boundaries.
- The challenge RED was collected with one independent `--case` runner invocation per frozen case so fail-fast oracle validation could not hide later mismatches; every invocation still performed exactly one fresh control check and one fresh static scan.
- Semantic value identity and storage invalidation are intentionally separate. Only Copy/Move, a structurally exact `&*` reborrow, stable projections, and pointer `Unsize` preserve an identity; dynamic index/subslice, ordinary casts, and derived slice/pointer operations fail closed or receive a fresh destination identity.
- Length facts are keyed by collection and static definition, capture reaching-write versions, carry a join-sticky invalidation tombstone, and retain relation uncertainty independently of the scalar result identity. This avoids both stale-length false negatives and write-after-recompute false positives in loops.
- Range-in-bounds and UTF-8 validation are authoritative only at exact local program points. They deliberately do not become cross-function validation contracts; unsupported or ambiguous arithmetic, provenance, version, or branch correlations fail closed. This remains a bounded registry implementation, not evidence of general Rust soundness.
- Validation contracts are represented as may-unmet routes. A locally proven route disappears; an unproven route is either a caller-checkable entry-formal contract or an unconditional hard requirement. Both sets join by finite union, so one unchecked callsite or graph route always preserves the candidate.
- Resolved-local mutable/raw actuals conservatively invalidate matching caller validations on the normal edge. This prevents a caller guard from surviving a local mutator; Task 7 may add precise output provenance but must not erase that write/havoc evidence.
- Local out propagation distinguishes definite writes from may-skip writes. A finite definite-out fixed point is frozen before the origin fixed point, so definite writes replace prior provenance, conditional writes preserve both possibilities, normal and unwind edges remain distinct, and an early approximation cannot leave stale output origins behind.
- Return and out effects remain separate channels. Normal edges apply mutable havoc, out effects, and the strong return destination in MIR order; opaque and FFI boundaries do not acquire fabricated local output summaries.
- Task 7 evidence used Cargo commit `15fbd2f607d4defc87053b8b76bf5038f2483cf4` and rustc/RAP compiler commit `1bc403daadbebb553ccc211a0a8eebb73989665f`. An earlier subset setup attempt used a binary without the embedded RAP compiler commit and was rejected before analysis; it is explicitly excluded from semantic evidence.
- Unresolved witness provenance uses finite one-hop summary edges keyed by the exact hard or conditional route fact. Summary fixed points union only these immediate edges; complete paths, path depths, and preferred witnesses are computed only after convergence and never enter the lattice.
- Witness selection is validity-neutral. Every exact root route must trace to an exact local seed or the analysis fails closed; only then is the shortest stable unresolved route selected. Recursive witness tokens are derived from route-specific SCCs intersecting that selected route, use a real resolved-local recursive call span, and do not change the finding ID.
- Checked-add range evidence is accepted only after the exact `usize::checked_add` result flows through the `TryTraitBranch` lang item and the Continue discriminant edge. The lang item alone cannot create evidence: only a pre-existing checked-end atom from the exact checked-add model can propagate. Ordinary add, wrapping/saturating arithmetic, the break edge, mixed definitions, stale writes, wrong collection/offset, and access-width mismatches remain unvalidated.
- The legacy fixed-array `saturating_sub` range guard is retained only when the normalized array extent is known on every reaching path and is at least the exact access width. Unknown slice lengths, mixed known/unknown extents, and under-width arrays fail closed.
- Rustc's pinned `span_to_location_info` returns one-based columns. The implementation therefore validates and preserves positive columns; the plan text proposing an unconditional `+1` was rejected because it would shift every existing span and finding ID. Compiler-generated locationless Nop/goto operations are retained as DTO slots with no source point, while every semantic operation that can affect a finding or validation continues to require a stable point.
- Standard-library pilot execution uses temporary driver and target directories outside the repository. A unit is successful only when the control and both scans stay within the pre-registered limits, the scans route exactly one receipt to that unit, and their path/resource-free normalized JSON is byte-identical; partial output is recorded only as a classified failure and cannot become success evidence.
- Standard-library sample selection is frozen before labels are created. Unknown labels, unknown rules, duplicate IDs, missing findings, incomplete interprocedural edge/mapping evidence, non-independent reviewers/adjudicators, and review files that do not bind the exact sample SHA fail closed. Samples below the pre-registered minimum are `inconclusive`, not failed merely because a small-sample Wilson interval is wide; early-stop and fabricated-edge failures remain immediate.
- The failed `core` run stops the original standard-library campaign before `alloc` by protocol. Any source-identity repair informed by this failure starts a new development-data campaign with a newly frozen RAP source commit/protocol; it cannot retroactively turn this gate into a pass or support an unseen-holdout precision claim.
- The independently frozen v2 campaign also stops at `core`, now because of its wall-time limit rather than source identity. Do not increase the limit or continue to `alloc`/`std` inside v2: any performance repair, resource-metric change, or longer budget requires a separately frozen development-data protocol. Until a complete deterministic unit receipt and the prescribed independent review exist, standard-library precision remains unmeasured.
- For the first performance repair, keep the existing synchronous SCC schedule rather than switching to in-place Gauss–Seidel, a delta worklist, fact caps, or a larger timeout. Those alternatives either expand the semantic review surface or hide the demonstrated scaling defect. Re-run all synthetic gates on the committed repair before freezing a v3 source commit; keep the 3,600-second core limit so success cannot come from relaxing the failed v2 acceptance line.
- The second performance repair keeps exact least-fixed-point semantics. It first removes clone-heavy joins, then separates CFG convergence from final replay and persists only call/sink validation snapshots, then separates local-output propagation from the one final full summary solve. Stable dirty caller scheduling, PlaceId interning, and relation watcher indexes are conditional follow-ups only if measured gates still fail.
- Production scanning has no approximate mode. Path depth, recursion, aliases, origins, facts, static write versions, and fixed-point rounds are never capped; external resource exhaustion produces no valid receipt.
- Sparse observation is defined by actual consumers, not by a heuristic state budget: every call operation is replay-observed, which covers all resolved-local boundaries and all P1–P6 registry sinks, while validation and entry-formal queries are frozen at that exact point. Whole-body relation facts are intentionally discarded only after materialization because later consumers use only aggregate origins and value-flow.
- The deep conditional optimizations are gated by measured failure, not by theoretical interest. Since the exact implementation already passed every 15/30/60-minute and 8/10/12-GiB development gate, further representation/worklist changes would add correctness risk without being necessary for release acceptance.
- The canonical finding set, rather than the complete witness-bearing receipt, is the cross-version semantic equality contract for the performance repair. Witnesses may change only to another deterministic route through real unresolved edges and must remain schema-valid.
- Analyzer optimization and target compilation profiles are separate contracts. `rapx-perf` inherits release optimization while retaining debug assertions and overflow checks; the analyzed crate continues to use ordinary development `cargo check`. A closed build-profile sidecar binds the declared analyzer profile to both actual binary SHA-256 values before a physical-footprint protocol may create output.
- macOS physical-footprint gating uses `proc_pid_rusage(RUSAGE_INFO_V4)` for every process-group member at each sample. Disappearing processes are ignored; API, permission, parse, and other sampling failures fail closed. RSS remains a secondary recorded metric. Historical v1–v3 protocols never initialize this API and continue to interpret their original `rss_limit_bytes` field as RSS.
- The v4 15/30/60-minute and 8/10/12-GiB gates are release performance gates, while the inherited 500-finding and 0.5-findings/KLoC lines are precision-campaign pause gates. Passing the former does not override the latter. The next permitted precision step is noise-root analysis of the already frozen samples, not a registry/rule change or a relabeled performance pass.
- The user selected one-person diagnostic labeling rather than the v4 two-reviewer protocol. The resulting labels may guide repairs but cannot support Cohen's kappa, adjudication, or a formal v4 precision pass. A final report must call the precision result diagnostic/inconclusive.
- Standard-library result presentation will group findings by an exact family key while retaining every active raw finding. The user also selected built-in hard suppression for audited standard-library invariants. To contain its risk, suppression is allowed only after full finding construction and causal dedup, only for exact rustc-commit/canonical-field matches, and only with a complete suppression ledger; it must never alter MIR transfer, summaries, routes, causal keys, or fixture behavior.
- The deterministic v4 noise audit is now materialized under `artifacts/unsoundaudit-v2/mac/stdlib-pilot/performance-v4/noise-audit/`: 876 raw findings form 77 exact families and a 124-finding diagnostic panel. One Rust unsafe-contract reviewer classified the panel as 91 C and 33 B, with no A/D/E/U and no fabricated route; the first-20-per-unit early-stop gate did not trigger. Population weighting assigns 839 findings in 54 families to exact type/constructor-invariant C candidates and retains 37 findings in 23 B families for generic guard/summary work. This is single-review development evidence only: it has no kappa, adjudication, Wilson interval, or formal precision-pass meaning.
- The C/B boundary is deliberately conservative. B families include `VecDeque::truncate`, `IntoIter::take_prefix/take_suffix`, slice `position/rposition`, checked capacity/spare-capacity relations, range-return contracts, and rotate pointer-offset propagation; these may not enter the stdlib allowlist. C candidates are restricted to pinned private representation/compiler-constructor contracts such as BTree handles, fmt Arguments, BorrowedBuf/Buffer counters, MPMC tokens, and exact saved-pointer/reference invariants. Suppression implementation must hash and bind each family review and preserve every B finding.

## Rejected Alternatives

- No nightly substitution, dependency upgrade, RAP lockfile edit, or source workaround for Mac compatibility.
- No cross-crate whole-program analysis, unresolved-call speculation, fixed iteration limit, name-based sanitizer, or keyword-only candidate rule.
- No FFI-return, Iterator, callback, general dynamic-dispatch, raw-reference/slice, `Box::from_raw`, or `set_len` extension in this work package.
- No permissive JSON Schema library fallback: the tracked standard-library validator enforces the exact contract directly and also audits the formal schema for drift.
- No Miri, target-code execution, Linux campaign access, coverage-ledger update, or historical-baseline reinterpretation. The separately approved static standard-library performance scans are the only real-project scans in scope.
