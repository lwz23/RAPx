# Standard-Library Active-Finding Audit

## Contract and scope

This is the closed validation inventory for the v5 standard-library active population. The committed population contains 37 unresolved findings grouped into 23 exact families; neither count is a confirmed-bug count.

The table was frozen from the committed v5 family reports and the committed v4 `family_reviews.json`. The **source evidence / proof pending** column records the existing single-review source rationale and cited spans; it is not promoted to a complete safety proof. At the Task 1 contract-freeze boundary no family was `confirmed_safe` or `confirmed_ub`; later task sections and the affected row record evidence-driven disposition changes.

Disposition meanings:

- `confirmed_safe`: a complete source/contract proof closes the family.
- `likely_safe`: existing source evidence suggests a false positive, but the proof is incomplete.
- `poc_required`: static evidence leaves a safe-call soundness question that needs a targeted PoC.
- `confirmed_ub`: a safe public call chain has reproducible UB evidence.
- `inconclusive`: available evidence cannot support another disposition.

The pinned `alloc::str::{join, concat}` family is now `confirmed_ub` for rustc commit `1bc403daadbebb553ccc211a0a8eebb73989665f`. A dependency-free application containing no `unsafe` reaches Miri-reported UB through the safe `join` and `concat` APIs when an entirely safe `Borrow<str>` implementation returns a longer string on its second call. This historical result does not establish that current Rust remains affected; current-toolchain validation and upstream duplicate search are still `not_started`.
